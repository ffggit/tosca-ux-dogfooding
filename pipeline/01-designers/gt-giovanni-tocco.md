| GT-008 | Giovanni Tocco | Prod | Builder | Test case editor / name field | Naming a new test case | Efficiency, Visual noise | Minor | After creating a test case, the name editor field is visually detached from the main blue CTA area where user attention is directed. Easy to miss. | |

| GT-011 | Giovanni Tocco | Prod | Scanner / XScan | Chrome browser | Scanning page elements | Help & guidance, Feedback | Major | XScan does not work on Chrome incognito windows. No error message or explanation is shown — it simply fails silently. Discovered only through trial and error. | |

| GT-013 | Giovanni Tocco | Prod | Scanner / XScan | Reports grid / row actions | Scanning download button in grid | Efficiency | Major | Buttons inside grid rows (download, delete) are difficult to scan individually. | GT-014 | Giovanni Tocco | Prod | Builder | Test case editor | Navigating away from unsaved test case | Efficiency, Error prevention | Major | No auto-save. A save dialog appears when navigating away, which is disruptive when it happens frequently. Modern SaaS products offer auto-save as standard — its absence feels outdated and causes frustration during iterative work. | Implement auto-save as standard in modern SaaS products, so the user doesn't have to remember to save every few minutes. |
| GT-015 | Giovanni Tocco | Prod | Scanner / XScan | Module rescan | Fixing a broken test step after UI change | Help & guidance, Efficiency | Major | A Rescan function exists in Build > Modules > [module] > Rescan, but is not discoverable from the test case editor or from a failed run. Users debugging a broken test step have no contextual shortcut to rescan the relevant module — they must navigate back through Modules manually. | Surface a "Rescan this module" action directly in the failed step's error context, so users don't have to navigate manually through Modules. |
| GT-016 | Giovanni Tocco | Prod | Test execution | Browser tab management | Running a test case | Feedback, Error prevention | Major | When multiple tabs with the same URL are open, Tosca throws "More than one matching tab was found" and fails. | |
| GT-017 | Giovanni Tocco | Prod | Test execution | Browser tab management | Running a test case | Help & guidance | Minor | It is unclear whether UseActiveTab should be True or False depending on the setup. No contextual guidance in the UI. | |
| GT-018 | Giovanni Tocco | Prod | Test execution | Run results / execution bar | Completing a test run | Feedback | Major | At the end of a run, the only signal is the execution bar losing its orange color. No result summary is shown (pass/fail). In On Prem, the scratchbook opens automatically with the log. Users must manually navigate to Runs to find results. | At the end of a run, take the user directly to the last run, or show a result somewhere (like in the execution bar) — similar to On Prem where the scratchbook opens automatically with the log. |
| GT-019 | Giovanni Tocco | Prod | Test execution | Run results / columns layout | Reviewing run results on VM | Efficiency | Minor | On a VM with a smaller viewport, the runs view is difficult to read without manually rearranging columns or collapsing the left panel. No auto-collapse or adaptive layout to help users prioritize relevant information. | Auto-collapse the left panel when the viewport is small, or other ways to help users prioritize relevant information. |
| GT-020 | Giovanni Tocco | Prod | Playlist | Playlist page | Running a playlist | Feedback, Error prevention | Major | After clicking Run, no feedback is given. No loading indicator, no confirmation the execution started. Clicking multiple times silently creates duplicate runs with no way to stop them. | Give feedback that the run has started and where to find it, or open it in front of the user's eyes to prevent duplicate clicks. |
| GT-021 | Giovanni Tocco | Prod | Playlist | Run history | Monitoring execution | Feedback, Consistency | Minor | During execution, live info is available but not presented as a progress bar. On Prem Commander offers a clearer visual progress indicator. | Offer live information as a progress bar (like On Prem). |
| GT-022 | Giovanni Tocco | Prod | Playlist | Run results | Reviewing results | Efficiency, Feedback | Major | After a run completes, only a generic "failed" status is shown. To understand which tests failed and why, the user must navigate through at least 3 clicks: open playlist → click failed → open run log. | |
| GT-023 | Giovanni Tocco | Prod | Playlist / Agent | OpenUrl / BrowserArguments | Running a playlist | Consistency, Feedback | Major | BrowserArguments set at test case level (e.g. browser=chrome) are ignored when the test runs via playlist using the Cloud agent.
